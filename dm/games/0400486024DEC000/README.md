# The Legend of Zelda: Ocarina of Time (`0400486024DEC000`)

A Switch 2 game: update v131072 over base v65536, from a `.nup` dump (base and update packages, each with its own ExeFS and RomFS; [NUP support](../../../android/NUP.md)). SDK 22.2.8 built for the Switch 2 (spec Ounce), NVN2. Nintendo EPD's engine (sead / agl / gsys, Phive, Havok), modules `main` + `subsdk0` (NintendoSDK movie 22.2.8) + `sdk`. **In bring-up: boots on Android to the title screen and its opening movie** ([Boot](#boot-android-v131072); not tried on the Mac or iOS). The profile, the Android rewrite and the shader library are made on Linux (no Mac). Its closest relatives here are [Mario Kart World](../0400C3F00006E000/README.md) (virtual address memory, a movie module, the same engine) and [Donkey Kong Bananza](../040074A01BF12000/README.md).

## What it needs

| Setting | Where | Why |
|---|---|---|
| `modules main subsdk0 sdk` | [`game.tsv`](game.tsv) | `subsdk0` is NintendoSDK movie 22.2.8 (824 exports); `main` imports its movie player (`nn::movie`, 34 imports), which the host does not supply, so it is loaded (as Mario Kart World's) |
| `sys_resource 0x3000000` | `game.tsv` | the NPDM declares 48 MB of system resource: virtual address memory on (as Mario Kart World; unlike Donkey Kong Bananza) |
| `mem_reserve 0x300000000`, `mem_alias 0x100000000` | `game.tsv` | **not measured**: Mario Kart World's layout, taken over because this game too has virtual address memory and sets a heap. The Mac heap check that sizes them was not run. On the phone they held so far: a 6.20 GB heap, and about 1.5 GB of the 4 GB alias region used so far. The 4 GB alias region also holds the SDK's 1 GB AddressRegionManager node area, which the SDK-wide cut (`dm/tools/sdk_patches.py`) does not reach on this `sdk` ([Rewrite](#rewrite-of-v131072)) |
| `app_pool 0x240000000` | `game.tsv` | the Switch 2's 9 GB, as Donkey Kong Bananza (not measured) |
| `render_cond on` | `game.tsv` | taken over from Donkey Kong Bananza and Tears of the Kingdom (agl's render buffer binding); not checked on this game |
| `shader_groups … /Layout2Shader/=layout` | `game.tsv` | Tears of the Kingdom's groups plus `Layout2Shader/` (the UI's `MergeShader`) |

The phone needs a GPU driver with `VK_EXT_map_memory_placed` (placed pools; the app's readiness check): the POCO F8 Pro's system Qualcomm driver (0800.71, Vulkan 1.3.284) lacks it, so it runs on Turnip (Mr_Purple's PurpleVK 26.3.0, T30). About 10.0 of the phone's 10.9 GiB were in use while it played, and Android ended background apps.

The SDK-wide rules "AddressRegionManager node area 1 GB → 62 MB" and "regions of 4 MB and more aligned to 2 MB" match no function of this `sdk` (a new implementation, not reviewed); the 4 GB alias region is sized to hold the 1 GB node area instead.

A diagnostic cut, off by default ([patches.py](patches.py)): `DM_OOT_MAX_RES=1` in the rewriter's environment holds the game's dynamic-resolution update (`main+0x805aa0`) at scale 1.0 by making its branch to the "dynamic resolution off" path unconditional (`main+0x805bd0` `e8410036` → `0f020014`), to tell the dynamic-resolution floor (683x384) and the NDSR upscaler apart from the black gameplay. Rewrite with it into a pack folder of its own (`--out`): the rewrite key does not cover the environment. Not yet tried on the phone.

## Boot (Android; v131072)

Phone: Xiaomi 2510DPC44G (POCO F8 Pro), Snapdragon 8 Elite (Adreno 830), 12 GB, Android 16 (HyperOS), Turnip ([What it needs](#what-it-needs)). Everything was built on Linux from the `.nup`: `profile_guess.py`, `pack_android.py`, `shader_split.py` and `vk_android_build.py` (the translator `dm/gfx/tools/dmsh_xlate_bin/dmsh_xlate.dll` through a `dotnet` wrapper; its source matches `dmsh_chain.lock`); test APK `-PnxApp=oot -PnxPackEngine=fake`.

First shader library: 42,321 shaders, 42,228 built; 19 fail to translate (Ampere instructions the translator does not implement, and the mesh program without a mesh layout, [Files](#files)) and 74 fail `spirv-val` (vector access out of bounds). A rebuild with the NDVE shaders (step 8) was running when this was written.

Each stop below was met on the phone in this order and fixed in the host (general fixes unless said otherwise; uncommitted, 2026-11-07):

1. **`auddmg:u` abort** at boot: Result 0xa99 at `sdk+0x1f61ac`, from SDK 22's `ListVirtualInputDevices` in the game's microphone manager (constructor `main+0xed1440`, open `main+0xf4860c`, list `main+0xf48128`), whether or not the voice ocarina is on. Fixed by a hook with no device; the game skips the open (`main+0xf4812c`). Checked on the phone. [Virtual input devices listed through `auddmg:u` (SDK 22)](../../../docs/reference/audio.md#virtual-input-devices-listed-through-auddmgu-sdk-22).
2. **gRPC abort** at boot: NPLN 1.55.1's `grpc_event_engine_init` aborts (`main+0x21f0c7c`) when its wakeup-fd check (`main+0x21f3bd0`) finds no eventfd. Fixed by local eventfds in `hle_net.c`. Checked: `socket: eventfd 512 made`, the engine starts. The flag values (Semaphore 1, NonBlock 4) are not checked. [Local eventfds for gRPC with the network down](../../../docs/reference/services.md#local-eventfds-for-grpc-with-the-network-down).
3. **SIGILL in a fiber switch**: `nn.npln.GrpcDispatcher` at `sdk+0x16d40c` (`autiasp` in `DispatchFiberContext`), the fiber's entry signed on another thread by `FiberImplByHorizon::Initialize` (`sdk+0x16d0d0`) with that thread's IA key. Fixed by turning the IA key off on guest threads. Checked with `DM_PAC_PROBE=1`: IA differed on all 85 threads before, unsigned on all 86 after, no crash. [Pointer authentication keys differ between Android threads (`nn::os` fibers)](../../../docs/reference/threads.md#pointer-authentication-keys-differ-between-android-threads-nnos-fibers).
4. **AV1 movies**: the movie library aborted (Result 0xfa86f, `subsdk0+0xf9bc`) when `InitializeAv1DecoderByTransferMemory` failed. Fixed by AV1 on `AMediaCodec` (`mavc_new_av1` in `dm/host/plat/movie_avc_android.c`, the AV1 family in `hle_codec_video.c`; the Mac and iOS still fail it). Checked: `c2.qti.av1.decoder` decodes 1920×1080, first picture, sound plays. [`nn::codec` video decoders taken over](../../../docs/reference/movies.md#nncodec-video-decoders-taken-over), [SDK 21's `nn::codec` entry points](../../../docs/reference/movies.md#sdk-21s-nncodec-entry-points).
5. **Controller applet every frame**: the game asks for exactly one player (`ShowControllerSupport` with 1 to 1); HyperOS's virtual device `uinput-xiaomi` was player 1 and the Bluetooth PlayStation pad player 2, and the host capped only the returned count, so the game's check (`main+0x3b262c0`, 3 for a controller past the wanted count) failed and it asked again. Fixed in `hle_hid.c` (`g_applet_cap`): players past the maximum are disconnected and feed player 1. Checked: the applet opens once, the pad's input reaches the game; `t_hid` 150 of 150 on the phone. The front end also stops giving a player at connect to a device with no stick and no A / B button (`GameActivity.java` `controller`), which leaves `uinput-xiaomi` out; not checked on the phone on its own. [The controller applet disconnects players past its maximum](../../../docs/reference/services.md#the-controller-applet-disconnects-players-past-its-maximum).

## Dynamic resolution

How the game picks its 3D size (v131072 main, disassembled 2026-11-14; agl's controller, the same family as Tears of the Kingdom's):

- **The controller's per-frame update** is `main+0x805aa0` (x0 = the controller, kept in x19; x1 = this frame's statistics, copied into it). It returns the scale in w0 (a float) and a state in the high word (2 when the level did not change). With bit 0 of its flag word (`ctl+0x188`) clear it returns 1.0 at once (`main+0x80640c`, the path the `DM_OOT_MAX_RES` diagnostic forces).
- **What it reads.** The GPU time of the last frame from a global profiler object (`[[main+0x4e81dd0]+0xc]`, stored at `ctl+0x9c`; the profiler is `main+0x5a8f0` per eden's notes), less a model of fixed costs and divided by the square of the current scale, so the history holds GPU time per full-scale frame. The history is a ring of pairs at `ctl+0x30` (size `ctl+0x28`); a least-squares fit over it (`main+0x805d74`…`+0x805e80`) predicts the next frame's cost (`ctl+0x3c`). The frame budget `ctl+0x10` is a table entry (`main+0x3f08694`, indexed by a 0-2 field of the frame statistics, which looks like the present interval) plus an offset. That the budget follows the present interval fits the issue 10 bursts after the game's 3 → 2 interval changes.
- **The levels.** A palette list at `ctl+0x190` (size `ctl+0x1a0`), node = {scale factor, level ID}; level 0 is the sharpest. The selector `main+0x8065e0` (w1 = the current level, s0 = the prediction) walks it and returns the index of the sharpest level whose predicted cost fits the budget, the last level when none fits, 0 when even full scale fits. The scale of a level is its factor times `ctl+0x7c`, rounded down to a multiple of `ctl+0x80`, over `ctl+0x90`. The palette of v131072 has 10 levels, 0.75 … 0.33334 (Banana Native eden's reading of `Pack/Bootup.Nin_Ounce_NVN2.pack.zs`, not read again here): about 1536x864 … 683x384 of the 2048x1152 the replay presents.
- **Moving between levels** (`main+0x805f98`…): a sharper level is taken only after a delay counter (`ctl+0x181`, reset from `ctl+0x1c8`) runs out; a less sharp one after another (`ctl+0x180`, from `ctl+0x1c4`), which the instructions after the call skip (they zero it) in some states (`ctl+0xa3`, `ctl+0xa8`). A level of -1 (no level) draws at scale 1.0 (`main+0x806378`).
- **Issue 10**: bursts of exactly 5 frames of about 1 s GPU (Adreno 840). Not proven, but consistent with the controller: the prediction or the budget lets it climb to a sharp level (or the -1 / full-scale state), and the down delay holds it there for a fixed number of frames before the slow frames reach the history.

**3D resolution** (Game settings, `DM_RES_LEVEL`; profile key `drs_level`): the host writes, at load, a branch at `main+0x805f8c` (the instruction after `bl main+0x8065e0`) to six to eight words in the zero padding at `main+0x8065c4` (7 words) and `main+0x806874` (3 words): `fixed:<n>` answers level n, `cap:<n>` at least n, both at most the palette's last (`ctl+0x1a0` - 1), and a step down is then always immediate. `fixed:lowest` is the palette's last level. The launcher's choices (the profile's `res_choice` rows): Max (level 0), High (1), Medium (4), Low (6), Lowest (9), and Dynamic never above High (`cap:1`) or Medium (`cap:4`); any other level is reachable with `DM_RES_LEVEL=fixed:<n>` in `env.txt`. A workaround on the game's own code; the cause (the controller tuned for the Switch 2's GPU, or the GPU time it reads) is open. What it does not touch: the full-scale path when the controller's dynamic resolution is off (flag bit 0), and the frames while the game holds its level itself (`ctl+0xa1` bit 0, which skips the selector).

Measured on the phone (2026-11-14, POCO F8 Pro, Adreno 830, Anka Turnip 1.0.0; Deku Tree 2F; each run started from 33.9 °C after a cool-down; frame rate over 10 s, game speed, GPU time a frame). "Before" is work/resolution before the NDSR stand-in took every level's network, "after" with it (`<work>/session-2026-11-14/resolution-cost.md`):

| Setting | Scene size | Before: fps / speed / GPU ms | After: fps / speed / GPU ms |
|---|---|---|---|
| Dynamic (the game's own) | before: 683x384 (its floor); after: levels 0 to 9 | 24.0 / 1.02x / 25.0 | 22.0 / 1.02x / 26.6 |
| `fixed:lowest` (level 9) | 683x384 | 20.0 / 1.00x / 25.7 | 20.0 / 1.00x / 24.5 |

Each level has its own upscaler network in `agl_ndsr_vr_light.pck` (levels 8-9 `d99fbeeb53d38847`, the others five more). Before, the NDSR stand-in replaced only `d99`, so every level from 0 to 7 ran its network at 30-64 ms of GPU a frame (61-75 ms in all where the floor takes 25), and Dynamic and both caps stayed at the floor. Now `DM_VK_NDSR_STANDIN` replaces all six ([agl's NDSR upscaler replaced by a bilinear stand-in on the Vulkan replay](../../../docs/reference/shaders.md#agls-ndsr-upscaler-replaced-by-a-bilinear-stand-in-on-the-vulkan-replay)): the GPU time follows the level (24.5 ms at the floor to 31.8 ms at level 0), every setting ran at full game speed, and Dynamic and the caps move between levels. The fps moves with the game's own frame pacing (its intervals give 20, 22, 26 and 30), so it is noisier than the GPU column (`fixed:0` above `fixed:1` is pacing, not GPU). Not measured: whether Lowest runs cooler, heat over a long run at a sharp level, other scenes, the handheld output size, and whether a cap stops the issue 10 bursts on an Adreno 840.

Side effects: the levels are the game's own, inside the render targets it allocates for its sharpest level, so no render target, texture pool or upscaler input outside what the game itself uses; the sharper levels raise the GPU work per frame (level 0 has about 5 times the pixels of level 9; 31.8 against 24.5 ms above). With any `DM_RES_LEVEL` value a step to a less sharp level is taken at once, without the game's down delay. The stand-in is bilinear, so the networks' added detail is gone at every level.

## Ground plants and stones

Game settings › Ground plants and stones (`DM_DETAIL`; profile rows `detail_setting`, `detail_level`, `detail_param`, `detail_env`, `detail_zsdic`; [the mechanism](../../../docs/reference/packing.md#game-settings--ground-plants-and-stones-the-games-own-parameter-files-edited-at-start)): Full (the default, sends nothing), Reduced (no moss or stones), Lowest (no small plants). The edits are the game's own foliage layer switches of every scene, set false in place in the copy the game reads, so the game itself decides what it draws: no draw is dropped, no shader or render target changes. **The Game settings row is hidden** (`detail_setting hidden`; a stored level sends nothing, `DM_DETAIL` in `env.txt` still works) until the phone has measured Reduced and checked Lowest's drops and climbable ivy (`<work>/session-2026-11-14/detail2.md`); showing it is that one row set to `shown`. The level ids `reduced` and `lowest` meant other rows in the unreleased rc2 builds (grass density, distances, effects), and a stored id is matched by name only: before the row is shown, clear `detail_level@0400486024DEC000` on the test phones that ran rc2 (with the app's data, before the first start of the build that shows the row; the owner's own phone is one), or a stored `lowest` silently becomes the new Lowest.

- **Reduced**: `IsEnableMoss` and `IsEnableStone` false in the 61 scene files of `Pack/Foliage.pack.zs` that have them. **Lowest**: also `IsEnableUndergrowth4` and `IsEnableUndergrowth8`. Never `IsEnableTurf` (the grass). The cuttable grass tufts and bushes are actors (`Obj_Plant_Grass_*`, `Obj_Plant_DestructibleGrass_Base`), not foliage layers: no level touches them.
- **Which copy the game reads** (phone, 2026-11-15, `DM_FS=1`): only `Pack/Foliage.pack.zs` (the overlay's copy opened as a host file); in Kokiri Forest not one loose `Foliage/ResFoliageScene` file was opened, so the profile names only the pack's members. The rewritten pack (one zstd frame of raw blocks, the source header with dictionary ID 4) is accepted. The overlay built on the phone from the player's `.nup` equals the PC's byte for byte.
- **Drops** (the game's data and code, read on the PC, 2026-11-15; not run): the cut and drop switches of foliage are fields of `game::foliage::ResShootLeaf` only (`EnableGrassCut`, `GrassCutEffectEmitRate`, `GrassCutBoost`, `NoDrop`, `OnWall`; field table at `main+0x2bf4740`). The game reads them in two places, both over its list of shoot-leaf types: `main+0xc958cc` writes each type's `EnableGrassCut` into the GPU's plant-type table (the GPU decides what a swing cuts), `main+0xc93150` builds the per-type table with `NoDrop` that the drop path reads. Every scene but `Market_Child` (`NoDrop`) takes `Game/FoliageDropParam/Default` (hearts, small magic jars, green rupees and others, `Pack/FoliageDropParam.pack.zs`). So per layer: **moss and stone: no drops possible** (`ResMoss` and `ResStone` have no cut or drop switch, and no table reads one); **Undergrowth4: drops possible** (4 of the 61 leaves of its list `Default4Leaf` set `EnableGrassCut` true, two of them Kokiri Forest's `Land_Kokiri_Plant_E_02` and `_E_04`, and none sets `NoDrop`; the other 57 cannot be cut); **Undergrowth8: no cut, so no drops possible** (medium-high, not run: its 13 leaves set neither `EnableGrassCut` nor a `$parent`, and the field registration at `main+0x2bf47bc` gives `EnableGrassCut` the default at `main+0x3eefdf8`, a 0 byte; the same table's other defaults are the expected ones, `GrassCutEffectEmitRate` 1.0, and the data sets the field true 82 times and false 18 times over the 203 shoot-leaf files, the value that differs from a false default). A cuttable kind can also be placed as an actor (`Component/FoliageParam/Land_Kokiri_Plant_E_02` names the same `ResShootLeaf`), which the layer switch may not reach, so which cuttable plants Lowest really removes is open. The default table (`Drop_Foliage_00`) also names the replace tables `RangeWeapon_01`, `Bomb`, `DekuNut`, `DekuStick` and `Fairy`, so a cut can give more than hearts, magic and rupees. The `Default4Leaf` list also holds the leaves of climbable ivy (`OnWall`, not cuttable); the walls' stems and backdrops are their own textures. Kokiri Forest (child) turns on Turf, Undergrowth4, Moss and Stone, not Undergrowth8.
- **Gains** (phone, POCO F8 Pro, rc2 `73e0852`, from 39.8-40.0 °C, 2026-11-15): all four layers off (`m_layers`, now Lowest): balcony 78.8 → 55.0-56.2 ms GPU (12.6 → 17.5-17.9 fps) in four starts, village −10.8 to −12.7 ms (camera not matched); no holes, no new red line. Reduced alone (moss and stone) is **not measured**. Each level makes 37-55 pipelines a cache built with Full lacks (10-20 s of creating, 2-3 skipped draws in the first window), once.
- **Rows that gained nothing** (same session; Full's spread 0.84-1.04 ms): grass density and blades x0.5 with the LOD distances x0.5 (the old Reduced) −0.48 ms balcony, +1.17 ms village; that plus SSAO, depth of field and bloom off and the dynamic shadows' far fade x0.5 (the old Lowest) −0.75 / +0.20 ms, with a visibly thinner picture. They are in no shown level: hidden measurement levels `m_turf`, `m_lod` (pack members only), `m_ssao`, `m_dof`, `m_bloom`, `m_shadow` (the `MainField` files). `m_ug`: the undergrowth layers alone (Lowest minus Reduced).
- **a1**, the game's handheld preset (`detail_env a1 DM_OPMODE=0`): a hidden level; only `DM_DETAIL=a1` in `env.txt` chooses it, until the phone shows that handheld runs none of the 9 NDSR networks the stand-in does not replace ([Open](#open)).
- **The pack's loader** (v131072 main): the resource decompressor reads the frame header (`ZSTD_getFrameHeader` at `main+0xe9790`, called from `main+0xe8f64` and `main+0xe8fa4`); a frame with dictionary ID 0 is decoded without a dictionary, any other ID is looked up in a tree of the registered dictionaries (`main+0x348c540`; the four `*.zsdic` members of `Pack/ZsDic.pack.zs`, IDs 1 to 4, `pack.zsdic` = 4). The allocation for a file comes from the frame's content size, rounded up to 32 (`main+0x505bb4`), so the frame must state it. Raw blocks store the pack's SARC as it is: about 8 times the compressed file on storage (88,799 → 746,008 bytes), the same in memory.
- **Shared values**: the game's BYML writer stores equal containers once: in `Graveyard_Adult` `LodSetting` and `LodSetting_hh` are one dictionary. The builder edits a stored value once, and only when every path to it is asked the same edit.
- **Where the overlay is**: `<DM_TEMP>_detail/detail-<levels>-<digest>/romfs/` (on the phone `files/temp/0400486024DEC000_detail/`), beside the game's temporary storage and not in it: `DM_TEMP` is the game's own `temp:` mount (it imports `MountTemporaryStorage`, `OpenDirectory` and `DeleteDirectoryRecursively`). The launcher removes the folder at a start with Full and logs one `[nxlaunch] Full (as the game draws it): …` line.
- **PC check** (`t_detail build` over the player's files of v131072; values in the scratch report only; 2026-11-15, `detail2.md`): see that report for the per-level counts; every file keeps its size and an independent reader finds only the intended values changed.
